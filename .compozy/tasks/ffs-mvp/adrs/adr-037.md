# ADR-037: Skills reach the substrate through an allow-listed in-process proxy

## Status

Accepted (2026-09-20, task_41)

## Date

2026-09-20

## Context

A skill bundle (ADR-009) talks to the substrate by writing `query` frames on its stdio; the skills host hands each frame to a `SubstrateAccess` implementation and writes the answer back. Since task_11 the daemon installed `RefuseAllProxy`, with a comment deferring "a real proxy that routes skill-side `query` frames through the dispatcher with the skill's identity" to Phase 2. That was harmless while the scribe returned its result in the invoke response and the courier wrote files. Task_41's auditor is the first skill that must read atoms (`atom.list`, `atom.get`, `ingest.list_pending`) and publish (`audit.publish_summary`) from inside the production daemon; without a proxy the daily summary and the briefing both fail silently in the binary, as the scheduler would have discovered on its first tick.

Per-skill identities (a capability grant per bundle, evaluated per query) are the right end state and are still deferred: they need a key per bundle, a grant flow in the installer, and the capability evaluator's agent identity threaded through the proxy. None of that is needed to make the auditor work, and none of it should be improvised.

## Decision

`ffs_daemon::DispatcherProxy` implements `SubstrateAccess` by handing the query to the daemon's own `Dispatcher` in process. Two restrictions hold until per-skill identities land:

1. **Skills act as the owner, on an allow-list.** The proxy accepts only the methods in `SKILL_ALLOWED_METHODS`: reads (`health.summary`, `atom.get`, `atom.list`, `entity.search`, `path.*`, `projection.render`, `predicate.inspect`, `audit.query`, `ingest.list_pending`, `ingest.list_auto_filed`, `courier.status`), `audit.publish_summary`, `ingest.submit`, and the librarian's `working_set.*` maintenance. Nothing that accepts, rejects, retracts, merges, unmerges, asserts identity, grants capabilities, federates, or submits a fast-path edit is reachable from a bundle. The human gate (ADR-029, ADR-030, ADR-032) therefore cannot be bypassed by skill code, however it was written.
2. **Installed after boot.** The host is built before the dispatcher (the dispatcher needs the host for the scribe), so the proxy starts with an empty slot and refuses with a clear message until `main.rs` installs the dispatcher; there is no window in which a query hangs.

The auditor scheduler (`FFS_AUDITOR_TICK_INTERVAL`, `FFS_AUDITOR_BRIEFING_INTERVAL`) is what makes the proxy load-bearing: it invokes the auditor from inside the daemon on its own intervals, and `audit.run` does the same on demand.

## Consequences

- The auditor publishes in production. The binary smoke in `crates/ffs-daemon/tests/briefing_binary_task41.rs` runs the real bundle through the proxy and the scheduler.
- A bundle that calls a denied method gets an error naming the allow-list, not a capability denial: the distinction tells a skill author "this is not yours to do" rather than "ask for a grant".
- When per-skill identities land, the allow-list becomes the floor, not the ceiling: a bundle's grant may narrow what it reads but never widens past this list without a new ADR.
- Extending the list is a deliberate edit to `skill_proxy.rs` with a test, not configuration; the list is short enough to review in one glance.
